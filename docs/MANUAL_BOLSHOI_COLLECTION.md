# Ручной сбор новостей Большого театра

Инструкция для рабочего приложения, развёрнутого через Docker Compose.
Команда собирает новости только источника `https://bolshoi.ru/news` и сохраняет
новые материалы в таблицу `items`. Она не запускает генерацию постов или
публикацию в Telegram. Эти этапы выполняются отдельными задачами.

## Перед запуском

Перейдите на рабочем сервере в каталог проекта:

```bash
cd /путь/к/bakhrushin_tg
docker compose ps
```

Должны работать PostgreSQL и контейнер `celery_worker`, в котором установлены
Playwright и Chromium. Проверьте, что источник Большого театра существует в
веб-панели и его тип — `html`.

В `parser_config` источника должны быть следующие поля. Добавьте их к
существующей конфигурации, сохранив фильтры ссылок:

```json
{
  "fetch_mode": "browser",
  "browser_channel": "chromium",
  "browser_state_name": "bolshoi",
  "browser_timeout_ms": 45000,
  "browser_wait_selector": "a[href*='/news/']"
}
```

Если доступ требует ранее полученных cookies, файл `.browser-state/bolshoi.json`
должен находиться в корне рабочего проекта. В контейнере он доступен по адресу
`/app/.browser-state/bolshoi.json`. Как получить и перенести сессию:
[Перенос cookies из Chrome на сервер](CHROME_COOKIES_TO_SERVER.md).

Наличие JSON-файла не гарантирует доступ: cookies могут истечь или не работать
с серверного IP. Кнопка «Тест» проверяет загрузку списка; команда ниже дополнительно
читает полные статьи, которых ещё нет в БД.

Не запускайте ручной сбор одновременно с другим сбором этого источника.
При необходимости временно остановите планировщик:

```bash
docker compose stop celery_beat
```

Уже запущенные или поставленные в очередь задачи после остановки Beat могут
продолжаться. Дождитесь их завершения. Сам `celery_worker` не останавливайте:
команда ниже выполняется внутри работающего контейнера. Если требуется исключить
AI-обработку и публикацию во время проверки, также дождитесь завершения ранее
поставленных задач этих типов.

## Запустить сбор только Большого театра

Выполните из каталога проекта:

```bash
./scripts/collect_bolshoi.sh
```

Если права исполнения не сохранены при переносе файлов, используйте:

```bash
bash scripts/collect_bolshoi.sh
```

Справка:

```bash
./scripts/collect_bolshoi.sh --help
```

Скрипт сам переходит в корень проекта, поэтому его можно вызывать и по абсолютному
пути из другого каталога. Он проверяет наличие Docker Compose и выполняет
сбор в уже работающем `celery_worker`. Сервисы автоматически не запускаются и
не останавливаются. При ошибке возвращается ненулевой код завершения.

Команда использует настройки источника из БД и запускает тот же HTML-сборщик,
что и регулярная задача. Она выполняется сразу в текущем терминале, а не через
очередь Celery. Источник может оставаться отключённым в панели: ручной вызов не
проверяет `enabled` и не включает его автоматически.

При успешном завершении обновляются время проверки и статус источника,
очищается предыдущая ошибка. При HTTP-ошибке или ошибке загрузки браузером
незавершённый сбор откатывается: новые материалы этого запуска не сохраняются.
Затем в карточку источника записываются ошибка, время проверки и HTTP-статус
(если он известен). Для 401/403 увеличивается счётчик последовательных отказов.
Скрипт не меняет состояние `enabled` и не отключает источник автоматически.

Для отказов 401/403 вместо traceback выводится понятное сообщение:

```text
Сбор остановлен: сайт Большого театра отказал в доступе (HTTP 401).
Cookies могли истечь или не подойти для этого подключения.
Получите свежие cookies в обычном Chrome, импортируйте их и перенесите bolshoi.json на сервер.
Инструкция: docs/CHROME_COOKIES_TO_SERVER.md
```

Далее выводится диагностика страницы и подтверждение записи ошибки в карточку
источника. HTTP 401 и заголовок страницы `HTTP 403` могут присутствовать вместе:
это ответ защиты сайта, а не противоречие в установке.

Код завершения `0` означает успешный сбор, `2` — отказ сайта 401/403,
`3` — другую HTTP-ошибку или ошибку загрузки браузером. Ошибки Docker и
непредвиденные программные ошибки также возвращают ненулевой код; последние
сохраняют traceback для диагностики.

Cookies от ранее успешно прочитанных страниц могли сохраниться отдельно от
транзакции БД. При отказе существующий файл сессии не удаляется. Обновите cookies
по [инструкции переноса](CHROME_COOKIES_TO_SERVER.md), проверьте доступ с сервера
и повторите `./scripts/collect_bolshoi.sh`.

## Как оценить результат

Пример вывода:

```text
Собираем: Большой театр — Новости, ID=2
Добавлено материалов: 2
Статусы всех материалов этого источника:
  new: 1
  rejected: 1
```

ID, число материалов и распределение статусов зависят от рабочей БД. Последние
строки показывают статусы **всех** материалов источника, а не только добавленных
текущим запуском.

- `Добавлено материалов: 0` может означать, что все найденные URL уже есть в БД,
  список пуст или материалы с известной датой отсеялись по сроку. Проверьте
  сообщения `[collect]`, значение `skipped_cutoff` и тест списка.
- `new` — материал ожидает обработки ИИ.
- `rejected` — материал сохранён, но не будет выбран обычной задачей генерации.
  Текущий HTML-сборщик отклоняет текст, если заголовок, краткое описание и полный
  текст вместе содержат менее 400 символов. Совпадение хеша текста с уже
  сохранённым материалом также приводит к отклонению.
- `ai_ready` — материал уже обработан ИИ предыдущими задачами.

Существующие URL не собираются повторно. Изменение cookies или повторный запуск
не обновляют текст и статус уже сохранённого материала.

Текущий сборщик извлекает ссылки со страницы списка в пределах `max_items`.
Он не перебирает страницы архива и не собирает карточки без отдельных ссылок.
Фильтр возраста применяется только при известной дате материала; дата Большого
театра может остаться неизвестной при текущем извлечении из URL.

## Ошибки

| Сообщение | Действие |
|---|---|
| Источник не найден | Проверьте наличие источника и его URL в панели. Команда ищет URL с завершающим `/` или без него. |
| Найдено несколько источников | Уточните записи в панели: команда не выбирает одну из них произвольно. |
| Источник должен иметь тип html | Исправьте тип источника. |
| `Executable doesn't exist` | Проверьте установку Chromium и пересоздание контейнера из нужного образа. |
| `Browser session bolshoi is busy` | Дождитесь завершения другого сбора или теста этой сессии и повторите команду. |
| `Cannot read browser session` | Проверьте формат JSON, доступ контейнера к файлу и повторный экспорт сессии. Не выводите cookies в логи. |
| HTTP 401/403, заголовок `HTTP 403` / Forbidden | Доступ отклонён сайтом. Проверьте свежесть cookies и серверный тест по инструкции переноса. Увеличение таймаута не снимает этот отказ. |
| Таймаут ожидания ссылок | Посмотрите диагностику страницы в ошибке: URL, заголовок, статус и число ссылок. Причиной может быть отказ защиты или изменение страницы. |

При ошибке доступа оставьте источник отключённым до успешной проверки.
Не запускайте `collect_all_sources()` для этой проверки: он обрабатывает все
включённые источники.

## Возобновить расписание

Если вы останавливали Beat и готовы возобновить фоновые задачи:

```bash
docker compose up -d --no-deps celery_beat
docker compose ps
docker compose logs --tail=100 celery_worker celery_beat
```

Запускайте только один экземпляр Beat. Возобновятся все задачи расписания,
включая сбор, AI и публикацию одобренных постов. Для регулярного сбора Большого
театра включите его в веб-панели после успешной проверки доступа.
